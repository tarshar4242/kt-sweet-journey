# AI 協作日誌產生器（Tarshar 專用．格式固定）

## 🔴 第一鐵則：先讀範本，再動手

動手前**一定要先讀** `docs/小熊健康小屋-AI協作日誌.html`（AI協作日誌 01，格式正本）與
`docs/AI咒語師護照-AI協作日誌.html`（AI協作日誌 02）。
沿用它們的 CSS 與版面結構，**不要自己設計新格式、不要改成 Markdown、不要做成索引式清單**。

## 這不是什麼（最常見的錯誤）

| 別做成 | 差在哪 |
| --- | --- |
| 索引式交接文件（檔案清單＋定案總表＋時間軸） | 那是 `project-handover-doc`，讀者是接手的人，不是這個 |
| 研究日誌 | 那是 `thesis-journal`，讀者是教授，會推進 Notion |
| 對話接力棒 | 那是 `chat-checkpoint`，讀者是下一個 Claude |
| .md 檔 | 協作日誌一律單檔 HTML，有封面、可列印 |

**AI 協作日誌的讀者是 Tarshar 自己與她的研究**：留下「我原本怎麼想 → AI 怎麼理解 → 哪裡偏了 → 我怎麼拉回來 → 形成什麼新規則 → 哪些能帶回研究」。

## 固定結構（照抄，不增刪部次）

**封面**：`AI協作日誌 NN`（流水號，接續既有最大號）＋專案名兩行＋`🍀 Learn AI with Tarshar | 2026`＋主題 SVG 插圖（沿用 cover 系列 class，換圖案即可）

**內容目錄**：10 列（導讀＋九部）

**導讀四節**
- `0.` 為什麼我要做這份日誌（含這次跟前一份的差異、是邊做邊記還是事後補寫）
- `1.` 這次協作的主線到底是什麼（通常兩條主線＋共同接點）
- `2.` 我和 AI 各自扮演什麼角色（幾方協作就寫幾方）＋「今天形成的協作原則」
- `3.` 專案與協作的底層安排（把關方式、單一事實來源、這次觀察到的落差）
- `4.` 資料安全與界線原則（依專案性質：家人隱私／孩子與未授權教材／個資）

**九部**
- 第一部：從需求到成果的完整紀錄（編號小節，逐段還原真實發生的事）
- 第二部：迭代／第二條主線的完整紀錄
- 第三部：**這次實際發生的偏航與修正**（最有價值的一部）
- 第四部：這次的正式決策帳（`<table>` 編號／決策／為什麼）
- 第五部：學習關鍵字辭典（術語｜中文＋「白話：」＋「本案例子：」）
- 第六部：可以帶回研究使用的素材（研究案例候補表＋證據狀態聲明）
- 第七部：這次產生的文件與狀態（正式支援文件／暫停待處理）
- 第八部：仍待確認（分小節）
- 第九部：現在正確的下一步（先做什麼＝Tarshar 先檢查這份文件的五點；接著做什麼）

## 寫作規則

1. **全文第一人稱「我」＝Tarshar**，不是 Claude 的口吻。AI 一律寫成「AI」「Claude」「Codex」。
2. **不美化、不事後合理化**。逐段還原真實發生的事，包含 AI 做錯的地方。
3. **第三部每一則固定三段**：AI 怎麼偏了 → 我的修正 → **可重複規則**（粗體，寫成下次能直接沿用的一句話）。
   - Claude 自己的錯也要寫進去，不可以只寫別人的。
   - AI 做對且值得保留的判斷，也可以收成正面案例。
4. **第五部辭典**每個詞都要有「白話」與「本案例子」兩層，白話要貼近小白的理解方式。
5. **第六部**編號接續前一份日誌（01 用了 001–005，02 用 006–010），並附「目前證據狀態」段落聲明尚未經指導教授確認、不能寫成研究結論。
6. 表格要用 `<thead>`／`<tbody>`，否則 CSS 不套用。
7. 結尾 `<p class="part-closing">` 收一句 Tarshar 口吻的話。

## 產出與交付

- 交付時**同一則訊息附上可直接點的連結或直接傳檔案**（依 CLAUDE.md 慣例）。
- 提醒 Tarshar 檢查第九部列的五點（有沒有漏掉、像不像她的意思、哪些是 AI 觀察卻被寫成已確定的規則）。
- 要不要收進網站系列，由 Tarshar 決定，不要自己上架。
